# v0.3 RAG Grounding Design

## Goal

Deliver ClaimGuard AI's first production-shaped, Chinese-first RAG workflow.
It retrieves a clause from a synthetic pet-insurance policy and attaches
traceable clause evidence to knowledge-grounded QA findings. API keys, indexes,
and customer data must never enter Git.

## Scope

This milestone changes the QA path from:

~~~text
conversation -> deterministic rule -> generic recommendation
~~~

to:

~~~text
Chinese conversation -> deterministic rule -> query -> Qwen embedding search
  -> retrieved clause -> grounded QA finding
~~~

RAG-001 through RAG-005 are in scope. Semantic and process rules remain
deterministic. Chat-completion models, LLM judges, and the Copilot reply writer
are not part of v0.3.

## Provider and Model Choice

The default provider is Alibaba Cloud Model Studio in mainland China. v0.3 uses
qwen3.7-text-embedding at 1024 dimensions for initial retrieval. This is the
officially recommended embedding model for instructed retrieval. The documented
1024-dimension default balances retrieval quality, storage, and cost.

The policy fixture contains only a few clauses, so v0.3 does not call a
reranker. The retriever interface leaves a reranker slot for a later release.
qwen3-rerank remains the planned default once the knowledge base is large
enough for initial retrieval to return a meaningful candidate set.

The default OpenAI-compatible endpoint is:

~~~text
https://dashscope.aliyuncs.com/compatible-mode/v1
~~~

The endpoint and model name can be overridden with environment variables for a
workspace-specific regional endpoint.

## Security and Data Locality

- The runtime reads DASHSCOPE_API_KEY only from the process environment.
- No source, fixture, index, log, exception, documentation example, commit, or
  release tag may contain a real API key.
- .env and .env.* remain ignored. ClaimGuard does not load .env files;
  environment setup stays under the operator's control.
- The implementation adds .claimguard/ to .gitignore; generated indexes live
  only below that ignored directory.
- v0.3 sends only synthetic policy clauses and a retrieval query to the
  configured embedding endpoint.

## Components

### Policy Parser

src/claimguard/knowledge.py parses Chinese Markdown policy headings in this
form:

~~~markdown
## 条款 12：免赔额
~~~

It returns ordered PolicyClause values:

~~~python
@dataclass(frozen=True)
class PolicyClause:
    id: str
    title: str
    content: str
    source_path: str
~~~

The parser rejects a document without clauses, duplicate clause IDs, blank
clause text, or unparseable clause headings. These are local validation errors;
the parser never makes a network call.

### Embedding Client

EmbeddingClient is a narrow protocol:

~~~python
class EmbeddingClient(Protocol):
    def embed(self, texts: list[str]) -> list[list[float]]: ...
~~~

DashScopeEmbeddingClient implements it through Model Studio's
OpenAI-compatible embeddings endpoint. It batches text, preserves input order,
requests 1024 dimensions, and validates that every vector is finite and has the
same dimension.

Configuration is read when the client is created:

~~~text
DASHSCOPE_API_KEY                 required for remote embedding calls
CLAIMGUARD_DASHSCOPE_BASE_URL     optional; mainland default above
CLAIMGUARD_EMBEDDING_MODEL        optional; qwen3.7-text-embedding by default
CLAIMGUARD_EMBEDDING_DIMENSIONS   optional; 1024 by default
~~~

Missing configuration and failed HTTP responses raise concise domain errors.
Messages identify the failed action but never disclose authorization values.

### Local Index

KnowledgeIndex stores policy clauses, vectors, the embedding model, vector
dimension, and an explicit schema version. It is inspectable JSON rather than a
database, and is generated only by an explicit index command.

~~~python
@dataclass(frozen=True)
class IndexedClause:
    clause: PolicyClause
    embedding: list[float]

@dataclass(frozen=True)
class KnowledgeIndex:
    schema_version: int
    embedding_model: str
    dimensions: int
    clauses: list[IndexedClause]
~~~

build_knowledge_index embeds each complete clause once. Save and load helpers
validate schema and vector lengths before the retriever can use the index.

### Retriever

retrieve_clauses(query, index, embedding_client, top_k=3) embeds the query,
calculates cosine similarity against the local index, and returns ordered
RetrievedClause values. Ties use clause ID order to keep results stable.

The retriever fails clearly when the query is blank, the index is empty, or a
query vector's dimension differs from the index. It does not silently fall back
to keyword search because that could hide a model or index mismatch.

### QA Grounding

rule_runner.py gains narrow Chinese detection paths for the five
knowledge-grounded V1 rules while preserving the English demo. For every matched
RAG rule, QA builds a retrieval query from the customer's relevant question and
the selected rule. It attaches GroundingEvidence to that finding:

~~~python
@dataclass(frozen=True)
class GroundingEvidence:
    clause_id: str
    clause_title: str
    clause_text: str
    source_path: str
    retrieval_score: float
~~~

Finding.grounding is optional, so the previous CLI result remains usable without
an index. This field is additive; all previous fields and score calculation stay
unchanged.

## CLI Contract

The existing QA command stays valid:

~~~text
claimguard <conversation.json>
~~~

Index creation is explicit:

~~~text
claimguard index <policy.md> --output <index.json>
~~~

Grounded QA adds an index path:

~~~text
claimguard <conversation.json> --index <index.json>
~~~

Only the index command sends policy text to the remote embedding API. Grounded
QA sends one retrieval query per run. The CLI returns non-zero with concise
messages for missing configuration, invalid policy data, corrupt indexes, or
remote embedding failures.

## Chinese Demo Data

The new Chinese policy fixture covers 免赔额, 等待期, 疾病保障范围, 意外定义,
and 拒赔依据与条款引用. Five Chinese conversation fixtures exercise those
topics. expected_risks remains test-oracle data only; runtime findings come
from the conversation and rule runner. The English claim-amount fixture remains
as a compatibility regression test.

## Testing Strategy

All automated tests are offline. They use a small in-memory embedding client
with hand-written vectors, while exercising the real parser, index serializer,
cosine ranking, QA report builder, and CLI boundaries.

Coverage includes valid and invalid Chinese policy parsing, index round trips,
vector validation, stable ranking, Chinese RAG-001 to RAG-005 detection,
report grounding fields, the legacy CLI path, and the new index CLI. A separate
manual command will validate a local demo index with DASHSCOPE_API_KEY; it is
not part of automated tests.

## Non-Goals

- No chat-completion model, LLM judge, or generated customer reply.
- No hosted vector database or background reindexing.
- No persistent secret store, .env loader, or key-management feature.
- No real insurance policy or production customer conversation data.
