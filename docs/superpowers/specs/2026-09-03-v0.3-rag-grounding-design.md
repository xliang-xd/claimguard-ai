# v0.3 RAG 依据能力设计

## 目标与范围

交付 ClaimGuard AI 首个接近生产形态、中文优先的 RAG 工作流：从合成宠物险保单检索条款，并把可追溯的条款证据附加到知识依据 QA 结论。API Key、索引和客户数据绝不能进入 Git。

QA 路径从：

~~~text
conversation -> deterministic rule -> generic recommendation
~~~

演进为：

~~~text
中文对话 -> 确定性规则 -> 查询 -> Qwen embedding 检索
  -> 检索条款 -> 有依据的 QA 结论
~~~

`RAG-001` 至 `RAG-005` 在范围内；语义与流程规则仍保持确定性。Chat-completion 模型、LLM Judge 和 Copilot 回复生成器不属于 v0.3。

## 服务商、模型与安全

默认服务商是中国大陆的阿里云 Model Studio。初始检索采用 1024 维 `qwen3.7-text-embedding`，以平衡质量、存储和成本。保单 fixture 较小，因此不调用 Reranker；知识库足够大后，计划使用 `qwen3-rerank`。

默认 OpenAI-compatible 端点如下，可由环境变量覆盖：

~~~text
https://dashscope.aliyuncs.com/compatible-mode/v1
~~~

- 运行时只从进程环境读取 `DASHSCOPE_API_KEY`。
- 源码、fixture、索引、日志、异常、文档、提交和发布标签不得包含真实 API Key。
- `.env`、`.env.*` 与 `.claimguard/` 保持忽略；生成索引只存放于被忽略目录。
- v0.3 只将合成保单条款和检索查询发送至配置的 Embedding 端点。

## 组件

### 保单解析器

`src/claimguard/knowledge.py` 解析以下中文 Markdown 标题，并按顺序返回 `PolicyClause`：

~~~markdown
## 条款 12：免赔额
~~~

无条款文档、重复条款 ID、空条款文本或不可解析标题都会触发本地校验错误；解析器从不发起网络请求。

### Embedding 客户端与本地索引

`EmbeddingClient` 是窄协议；`DashScopeEmbeddingClient` 通过 Model Studio 的 OpenAI-compatible embeddings 端点实现它。它批量处理文本、保持输入顺序、请求 1024 维，并校验向量有限且维度一致。

~~~text
DASHSCOPE_API_KEY                 远程 embedding 调用必填
CLAIMGUARD_DASHSCOPE_BASE_URL     可选；默认中国大陆端点
CLAIMGUARD_EMBEDDING_MODEL        可选；默认 qwen3.7-text-embedding
CLAIMGUARD_EMBEDDING_DIMENSIONS   可选；默认 1024
~~~

`KnowledgeIndex` 将保单条款、向量、Embedding 模型、维度和 Schema 版本保存为可检查 JSON。它不是数据库，只能通过显式索引命令创建；加载前会校验 Schema 和向量长度。

### 检索与 QA 依据

`retrieve_clauses(query, index, embedding_client, top_k=3)` 对查询做 embedding，与本地索引计算余弦相似度，并返回稳定排序的 `RetrievedClause`。空查询、空索引或维度不匹配会明确失败，不静默回退到关键词检索。

`rule_runner.py` 为五条知识依据 V1 规则增加中文检测路径，同时保留英文演示。每个命中的 RAG 规则都会把 `GroundingEvidence` 附加到结论。`Finding.grounding` 是可选补充字段，既有 CLI 字段和得分计算保持不变。

## CLI 契约

~~~text
claimguard <conversation.json>
claimguard index <policy.md> --output <index.json>
claimguard <conversation.json> --index <index.json>
~~~

只有索引命令会向远程 Embedding API 发送保单文本；有依据 QA 每次发送一个检索查询。缺少配置、无效保单数据、损坏索引或远程 Embedding 失败时，CLI 以非零状态和简洁信息退出。

## 演示数据、测试与版本

中文保单 fixture 覆盖免赔额、等待期、疾病保障范围、意外定义和拒赔依据与条款引用；五个中文对话 fixture 对应这些主题。`expected_risks` 仅是测试预期数据，运行时结论来自对话和规则运行器。英文赔付金额 fixture 仍是兼容性回归测试。

自动化测试离线执行，以带手写向量的内存 Embedding 客户端覆盖解析、索引序列化、余弦排序、QA 报告和 CLI 边界。手动命令可用 `DASHSCOPE_API_KEY` 验证本地演示索引，但不属于自动测试。

此能力发布采用软件包版本 `0.3.0` 与 Git 标签 `v0.3.0`。非目标包括 Chat-completion 模型、LLM Judge、生成回复、托管向量数据库、后台重建索引、持久化 Key 管理，以及真实保险或生产客户数据。
