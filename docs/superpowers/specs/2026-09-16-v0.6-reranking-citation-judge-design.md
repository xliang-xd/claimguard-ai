# v0.6 Reranking 与 Citation Judge 设计

## 目标

v0.6 将 ClaimGuard AI 的 Policy Copilot 从“按指令尝试依据条款回答”升级为“只在可验证证据支持草稿时交付”。本阶段仅覆盖文字客服中的保单问题；现有 QA CLI、确定性规则和语义质检保持独立。

成功路径为：

```text
客户问题
  -> Embedding 召回候选条款
  -> Qwen Reranking 排序
  -> Policy Agent 使用选中证据生成客服草稿
  -> Citation Judge 核验草稿是否被本轮证据支持
  -> draft_ready 或 human_takeover
```

## 范围

本阶段实现：

- `Reranker` 抽象、Qwen Reranking provider 与可注入离线替身。
- Policy Tool 中的召回后排序与最小分数过滤。
- 每轮 Copilot 运行时的内存 Evidence Ledger。
- 结构化 `CitationVerdict` 与 Qwen Citation Judge。
- Citation Judge 通过后才允许 Runtime 返回并保存 `draft_ready`。
- 离线评测集：正确支持、不完整支持、错误条款、无证据。
- v0.6 中文文档、技术图、版本元数据和测试记录。

明确不做：

- Claims、Complaint、完整 Compliance Guard、审批或副作用工具。
- 持久化 Session、跨进程 Evidence Ledger 或 Web/API 工作台。
- 将 Citation Judge 接入既有 QA CLI。
- 将模型输出、原始客户消息、草稿正文或条款正文写入本地审计事件。

## 模型与边界

| 能力 | 模型 | 选择理由 |
| --- | --- | --- |
| Embedding | `qwen3.7-text-embedding` | 保持 v0.5 索引兼容性。 |
| Reranking | `qwen3-rerank` | 对召回候选按问题与条款语义重排，降低错误条款进入上下文的概率。 |
| Policy Agent | `qwen3.7-plus` | 生成客服草稿，现有国内模型配置保持不变。 |
| Citation Judge | `qwen3.7-plus` | 对草稿与受控证据做结构化支持性判断。 |

所有模型经现有 Qwen Provider/Model Studio 中国大陆 endpoint 调用。OpenAI 托管 tracing 默认关闭。真实模型调用仅在受控 smoke 或显式启用的运行路径中发生；单元测试使用假 Reranker、假 Judge 和假 Runner。

## 组件设计

### Reranker

`Reranker` 接收查询与召回候选，返回带分数的稳定排序结果。接口要求：

- 候选 ID 必须唯一，输入与输出集合必须一致。
- 分数为有限数值；并列时按原始召回顺序和条款 ID 稳定排序。
- Provider 错误不暴露 Authorization、API Key、URL 参数或响应正文。

Policy Tool 的顺序固定为：Embedding 召回 `top_k` 候选，Reranking，再按 `minimum_score` 过滤。未剩余证据时返回 `no_evidence`，不得生成或猜测条款。

### Evidence Ledger

`EvidenceLedger` 是挂载在 `CopilotContext` 的仅内存对象。它由 Policy Tool 成功检索后写入本轮证据快照：

- `clause_id`
- `title`
- `content`
- `source_path`
- `retrieval_score`
- `rerank_score`

Ledger 的正文仅传入 Policy Agent 和 Citation Judge，不写入 `AuditEvent`，也不跨进程持久化。审计只保留条款 ID、数量、分数区间、判定状态与匿名化事件 ID。

### Citation Judge

Judge 输入为最终客服草稿及本轮 Ledger 中的证据。输出固定为：

```text
status: supported | unsupported | insufficient_evidence
citations: 非空条款 ID 列表
reason_code: 受控枚举
```

Judge 输出满足以下约束：

- `supported` 必须至少引用一个本轮 Ledger 中存在的条款 ID。
- `unsupported` 与 `insufficient_evidence` 不允许携带可交付草稿。
- 未知条款 ID、无效 JSON、模型/网络错误均视为失败。
- Judge 只返回受控结构化结果；详细推理不进入用户输出或审计。

## Runtime 门槛

Policy Agent 的 `draft_ready` 不再是最终交付状态。Runtime 在取得 Agent 输出后：

1. `human_takeover` 直接保留。
2. `draft_ready` 必须存在本轮 Evidence Ledger 证据。
3. 调用 Citation Judge。
4. 仅 `supported` 允许保存会话并返回 `draft_ready`。
5. 其他 Judge 结果或任何异常均记录元数据审计后返回空草稿的 `human_takeover`；不得保存成功会话状态。

成功审计包含 Agent 名、引用条款 ID、证据数量与受控 verdict；失败审计仅包含失败类别和 `human_takeover`。所有现有租户、用户、会话隔离与每会话串行化规则保持不变。

## 测试与评测

离线测试覆盖：

- Reranking 的排序、过滤、错误脱敏与稳定性。
- Ledger 仅记录真实工具证据且不进入审计。
- Citation Judge 对四类评测样本输出正确结构化 verdict。
- Runtime 在 Judge 通过时保存会话，在失败、异常、无证据或伪造引用时不保存成功状态。
- 多轮与并发会话仍保留 v0.5 的隔离保证。

评测 fixture 使用合成宠物险条款和对话。真实 Qwen smoke 测试单独记录，必须确认输出不含密钥、OpenAI 托管 tracing 关闭、且失败不会把草稿交付。
