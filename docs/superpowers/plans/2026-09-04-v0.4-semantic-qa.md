# v0.4 语义质检实施记录

## 目标

在不改变默认离线确定性行为的前提下，为已完成对话增加可选、结构化的 Qwen 语义质检结论。

## 工作项

1. 新增 `SemanticJudgeClient`、`SemanticJudgment`、严格响应解析和安全错误边界；默认模型为 `qwen3.7-plus`，请求使用 `temperature: 0` 与 `enable_thinking: false`。
2. 将验证后的 `SEM-002` 至 `SEM-005` 结论合并进 QA 报告，加入 `reasoning`、`confidence` 和 `judge` 补充字段；证据必须精确等于一整条客服消息，确定性结论优先去重。
3. 为对话 QA 增加惰性的 `--llm`，禁止将该标志用于 `index`；服务商错误不泄露 Key 或请求细节。
4. 更新文档、架构图、Agent 编排图和路线图，将语义质检标记为当前能力；版本提升至 `0.4.0`。

## 验证

自动测试使用注入响应，保持离线：

```bash
python3 -m unittest discover -s tests
PYTHONPATH=src python3 -m claimguard.cli examples/conversations/claim-amount-dispute.json
```

手动受控验证可在被忽略的 `.env` 已配置后运行：

```bash
PYTHONPATH=src python3 -m claimguard.cli examples/conversations/zh-semantic-qa.json --llm
```

该命令会产生模型费用；输出只接受完整客服引文支持的结论。Citation Judge、Reranking、Copilot、持久化和 Web/API 仍延后。
