# v0.3 RAG Grounding Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

**Goal:** Add a Chinese-first, Qwen-embedding RAG workflow that grounds V1 knowledge QA findings in traceable policy clauses.

**Architecture:** Parse a synthetic Chinese Markdown policy into clause records, create an explicit local JSON vector index through the Model Studio embedding endpoint, and use cosine retrieval to attach a clause citation to RAG findings. The existing deterministic report remains usable when no index is supplied; all external calls stay behind one embedding-client boundary.

**Tech Stack:** Python 3.9+, standard library HTTP and JSON, unittest, Alibaba Cloud Model Studio OpenAI-compatible embeddings API, qwen3.7-text-embedding at 1024 dimensions.

**Spec:** docs/superpowers/specs/2026-09-03-v0.3-rag-grounding-design.md

## Global Constraints

- Read DASHSCOPE_API_KEY only from the process environment. Never write or log an actual key.
- Use the mainland China endpoint https://dashscope.aliyuncs.com/compatible-mode/v1 by default.
- Keep generated vector indexes below .claimguard/, and add .claimguard/ to .gitignore.
- Automated tests must run offline without a key or network access.
- Preserve the existing QA CLI invocation and existing report fields; grounding is additive.
- Keep the existing English fixture passing and make Chinese fixtures the v0.3 primary path.
- Each task ends with a commit and a push of codex/v0.3-rag-grounding.
